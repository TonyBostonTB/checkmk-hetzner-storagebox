# Changelog

## 0.2.0 - 2026-07-28

### Fixed

- **Requires CheckMK 2.4 or later, now including 2.5.** The rulesets used
  `cmk.gui.form_specs.private.LegacyValueSpec` to bridge one custom widget
  (the result-cache editor) from the legacy `cmk.gui.valuespec` API into the
  new `cmk.rulesets.v1` rule form. That private compat module was removed in
  CheckMK 2.5, which broke loading of `rulesets/hetzner_storagebox.py`
  entirely.
- The result-cache option (`cache_enabled` in the special agent rule) is now
  a native `CascadingSingleChoice` ("Disabled" / "Enabled" with a nested TTL
  + stale-on-error `Dictionary`), matching the tuple shape
  `server_side_calls/hetzner_storagebox.py` already expected. Old stored
  rules (bool, flat dict, or legacy top-level `cache`/`cache_ttl`/
  `cache_stale_on_error` keys) are migrated automatically.
- `cache_stale_on_error` is now `required=True` inside its `Dictionary` to
  avoid the double-checkbox rendering artifact optional `BooleanChoice`
  elements have in Checkmk's current form-spec renderer.
